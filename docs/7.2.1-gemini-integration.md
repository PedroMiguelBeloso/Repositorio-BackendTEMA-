# Adaptador Gemini para aplicabilidad condicionada

La verificación usa `ApplicabilityAiPort` para las evidencias con modo `CASE_DEPENDENT`. La regla `ALWAYS` sigue siendo determinista; las notas y hechos expresados en texto libre se envían a la IA para evitar inferencias erróneas basadas en palabras aisladas o negaciones. El adaptador envía a Gemini únicamente el contexto preparado por M2: nombre de la evidencia, tipo de servicio, políticas, instrucciones y hechos del alcance autorizado. Gemini propone `APPLIES`, `NOT_APPLICABLE` o `UNDETERMINED`; no determina cumplimiento ni busca archivos o tickets por su cuenta.

## Configuración local

El proveedor predeterminado es Gemini. No se necesita una clave de OpenAI. En la misma sesión de PowerShell desde la que se inicia Spring Boot:

```powershell
$env:TEMA_AI_PROVIDER='GEMINI'
$env:GEMINI_API_KEY='<clave-entregada-por-TEMA>'
$env:TEMA_GEMINI_MODEL='gemini-3.5-flash-lite'
$env:TEMA_GEMINI_TIMEOUT='PT20S'
.\mvnw.cmd spring-boot:run
```

Guardar la clave en una variable de entorno o en un gestor de secretos, nunca en `application.properties`, Git, un ticket o una captura. `TEMA_GEMINI_MODEL` y `TEMA_GEMINI_TIMEOUT` tienen esos valores por defecto. El backend inicia sin clave; en ese caso la aplicabilidad queda `UNDETERMINED` para revisión humana. `TEMA_AI_PROVIDER=NONE` desactiva la interpretación automática. Para volver a usar el adaptador anterior: `TEMA_AI_PROVIDER=OPENAI`, `TEMA_OPENAI_ENABLED=true`, `OPENAI_API_KEY` y `TEMA_OPENAI_MODEL`.

`TEMA_GEMINI_API_BASE_URL` apunta por defecto a `https://generativelanguage.googleapis.com`; solo se cambia para un servidor de pruebas. La clave se envía en la cabecera `x-goog-api-key` de una petición HTTPS al método `generateContent`, no en la URL. No se registran la clave, el prompt ni datos del ticket.

## Respuesta y errores

Se solicita JSON con un esquema explícito y se comprueba localmente que el ID de expectativa coincida, que la decisión sea válida y que todas las referencias citadas pertenezcan a los hechos recibidos. Una decisión `APPLIES` o `NOT_APPLICABLE` debe citar al menos un hecho; su fundamento específico queda en el resultado. Una salida incompleta o inválida permite un segundo intento. Los errores de transporte y HTTP 429/5xx también permiten un reintento acotado; 401/403/404 no se reintentan. Si Gemini no responde correctamente, la aplicabilidad queda `UNDETERMINED` para revisión humana, con una limitación sin secretos. El log registra solo categorías y número de intento. El timeout configurable máximo es 60 segundos por llamada.

Cuando el mismo registro documental aparece como registro de actividad y salida de una macroactividad, la verificación conserva ambos resultados, pero reutiliza una sola propuesta de aplicabilidad para ese registro dentro de la ejecución. Esto evita decisiones contradictorias de IA para dos ubicaciones de la misma evidencia.

No hay cambios de API pública ni de esquema SQL. `AiApplicabilityAssessment` conserva la decisión propuesta, razón, referencias, limitaciones, modelo y `responseId` si Gemini lo entrega. Las pruebas usan un servidor HTTP local de prueba y no consumen la API real.

Referencia: [Gemini API, `generateContent`](https://ai.google.dev/api/generate-content).
