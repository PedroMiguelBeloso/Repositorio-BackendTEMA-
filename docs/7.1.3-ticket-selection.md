# WBS 7.1.3 — Selección de tickets

`POST /api/v1/verifications` vuelve a resolver el preview con el alcance solicitado. La solicitud aporta `serviceRevision` y una selección (`groupId`, `ticketIds`) por cada grupo obligatorio de ese alcance; no define ni sustituye los grupos del proceso publicado.

El caso de uso valida la revisión del servicio, la cardinalidad y la lista de IDs de cada grupo. `ONE` acepta exactamente un ID y `MULTIPLE` acepta uno o más. Cada ticket seleccionado se consulta individualmente a través de `RedmineTicketReader` y se verifica contra el proyecto Redmine configurado para el servicio. Una consulta fallida cancela el inicio.

Solo después de validar todos los grupos se crea la ejecución `QUEUED` y se insertan sus filas de `verification_ticket_selections`, dentro de una única transacción. La revisión del servicio se bloquea y comprueba de nuevo durante la escritura. Los IDs quedan ligados a la ejecución y no se actualizan; una nueva selección requiere otra ejecución.

Las expectativas TICKET de una macroactividad comparten el grupo de esa macroactividad. Los grupos de macroactividades distintas se validan independientemente. Las evidencias documentales no multiplican sus resultados por el número de tickets usados como contexto.
