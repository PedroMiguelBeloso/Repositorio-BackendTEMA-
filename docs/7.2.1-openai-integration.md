# TC-178 — integración de OpenAI para aplicabilidad

## Límite funcional

`ApplicabilityAiPort` responde una sola pregunta: si una expectativa `CASE_DEPENDENT`
aplica a un caso. No evalúa cumplimiento, no selecciona evidencias y no consulta
Drive ni Redmine. El evaluador de M2 (TC-179) intentará primero una decisión
determinística y llamará al puerto solo cuando necesite interpretar texto.

```
Evaluador M2 (TC-179)
  -> AiApplicabilityRequest (expectativa + contexto autorizado)
  -> ApplicabilityAiPort
      -> OpenAiApplicabilityAdapter -> Responses API, JSON Schema
  <- AiApplicabilityAssessment (APPLIES / NOT_APPLICABLE / UNDETERMINED)
  -> comprobación de la evidencia o revisión humana
```

## Paquetes y clases

- `verification.domain.ApplicabilityDecision`: los tres resultados de aplicabilidad.
- `verification.application.AiApplicabilityRequest`: contexto acotado. Incluye el ID y
  nombre de la expectativa, políticas e instrucciones pertinentes, tipo de servicio
  y hechos con referencias estables. El llamador solo puede construir hechos de los
  tickets seleccionados y de otras fuentes autorizadas de la ejecución.
- `verification.application.AiApplicabilityAssessment`: propuesta y límites; no es
  el estado final de cumplimiento.
- `verification.application.ApplicabilityAiPort`: frontera consumida por M2.
- `verification.infrastructure.ai.OpenAiClientConfig`: habilita el adaptador cuando
  existe una clave y un modelo; en otros entornos deja el puerto operativo con
  respuesta `UNDETERMINED`.
- `verification.infrastructure.ai.OpenAiApplicabilityAdapter`: serializa el
  contexto, llama al SDK oficial, valida ID/enum/referencias y limita los reintentos.

El texto de tickets y políticas se envía como datos. La instrucción fija de la
aplicación indica al modelo que ese texto no puede cambiar las reglas ni habilitar
herramientas. No se configuran herramientas del modelo. Las referencias devueltas
deben existir entre los hechos que se enviaron; una referencia inventada invalida
la propuesta. La entrada se limita a 20.000 caracteres. Si es mayor, queda
`UNDETERMINED` en vez de recortarla silenciosamente.

## Configuración

Se usa `com.openai:openai-java` ya presente en Maven y la Responses API con
salida estructurada. No se agrega Spring AI ni una base vectorial.

| Variable | Uso |
| --- | --- |
| `TEMA_OPENAI_ENABLED` | `false` por defecto. Activar solo en un entorno con clave y modelo. |
| `OPENAI_API_KEY` | Clave de proyecto, configurada fuera del repositorio. |
| `TEMA_OPENAI_MODEL` | Nombre de un modelo con soporte de Structured Outputs. |
| `TEMA_OPENAI_TIMEOUT` | Duración ISO-8601; `PT20S` por defecto, hasta `PT60S`. |

El backend inicia sin clave. En ese caso, una consulta que necesitaba IA queda
indeterminada con una limitación; no se simula una decisión. El SDK tiene un
reintento de transporte configurado. Ante una respuesta del modelo inválida se
permite un segundo intento; después se devuelve `UNDETERMINED`.

Las solicitudes usan `store=false`. Esto evita almacenar la respuesta como estado
recuperable de la aplicación de OpenAI; no implica por sí mismo retención cero en
todos los sistemas. No registrar la clave, los prompts ni el texto del ticket en logs.

## Integración pendiente en TC-179

TC-178 deja listo el puerto y su adaptador. TC-179 debe construir el
`AiApplicabilityRequest` desde el proceso publicado y el caso autorizado, invocar
el puerto solo tras descartar una regla determinística suficiente y traducir la
propuesta a la evaluación de M2. Si llega `UNDETERMINED`, el resultado queda
por revisar. Si llega `APPLIES` para un documento, la búsqueda posterior sigue
siendo determinística por nomenclatura en Drive.
